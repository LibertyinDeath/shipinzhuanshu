# 转写稿整理成书的方法（三遍提纯工作流）

> 来源：2026-11-03/04 深夜实战——把「卉哥·朋友圈灵魂收钱」（12 节课约 20 万字）整理成《朋友圈发布标准手册》、把「贝琳达销售逻辑课」（74 节课约 75 万字）整理成六卷 54 章 19 万字的 EPUB + MD 单本。本文档把这套打法沉淀成可复用的标准流程。
> 适用：课程音频/视频转写稿、直播逐字稿、聊天记录合集 → 可读的电子书（EPUB/MD）或标准手册。

---

## 一、总原则（先立规矩再动手）

1. **忠实原文是底线**：整理是"去杂、成段、加骨架"，不是改写。观点、方法、案例、数字、金句一样都不能丢，说话人的原话风格要保留。
2. **口径先谈定**：动手前必须和需求方（宝总）确认三件事——重叠内容怎么处理、交付形式（单本/分册）、敏感内容收不收。口径不清就动手 = 返工。
3. **保留率要有预期**：语音转写稿的水分极大（互动、重复、口水占 50-70%）。最终成书体量通常是原稿的 **25-30%**，这是正常的，不是丢内容。
4. **口径靠验收迭代收敛**：第一卷/第一批一定先出试读版让需求方验收，确认密度和文风后再批量生产，避免 75 万字全做完才发现"太啰嗦"。

---

## 二、第一步：素材盘点（半小时，必做）

动手前把素材摸清，产出一张盘点表：

1. **数清楚有什么**：文件数、总字数（`wc -c`/`wc -m`）、文件命名规律、有没有总目录/对照目录。
2. **分类**：按内容类型分堆（如：文字稿版 / 直播逐字稿版 / 会员答疑 / 辅修短课），每类抽一个文件读开头 1KB，判断原文质量。
3. **识别重叠**：不同版本讲同一节课的（如"文字稿版 vs 直播逐字稿版"）列成对照表，后面合并用。
4. **识别质量问题**：
   - 直播聊天流整理的稿子往往**同一段话重复几十遍**（刷屏被原样记录）——干货可提取但要去重；
   - 有些课的知识在视频画面里、聊天流里只有寒暄（几乎无内容）——如实标注，不硬凑；
   - **源文件可能本身截断**（转写没跑完）——动笔前抽查文件结尾，发现截断记录在案，整理时不虚构缺失内容。

---

## 三、第二步：定口径（与需求方确认）

三个必答题：

| 问题 | 选项 | 本轮实战的定案 |
|---|---|---|
| 同题多版本怎么处理 | ① 全量都收（存档）② 去重合并（一版为主干、另一版补新增） | 去重合并：文字稿为主干，逐字稿只补新增观点/案例/话术 |
| 交付形式 | ① 单本大书 ② 按卷分册 | 单本 EPUB（微信读书导入）+ 补一个 MD 单文件版 |
| 敏感内容 | ① 照收 ② 筛掉敏感行业 ③ 到时候再说 | 答疑照收不筛 |

另外确认**成书结构**：按主题逻辑重排分卷（认知→获客→转化→私域→修己→答疑），而不是按课程编号原序堆——原序是录制顺序，不是学习顺序。

---

## 四、第三步：提纯标准（核心方法论）

### 演进过程（为什么要三遍）

- **一遍清洗**（去杂+成段+小标题）：需求方反馈"保留太多"；
- **二遍精编**（案例压到 2-4 句、砍重复例证）：仍嫌口语多；
- **三遍提纯（最终定稿口径）**：彻底去口语、观点化成文。

**教训：直接按三遍口径一步到位，不要分三遍做。** 三遍是验收迭代的结果，不是必要工序。

### ✅ 最终口径：三遍提纯（可直接抄用）

1. **去杂**：删除投喂头信息、时间戳、说话人标签（Speaker 1:）、飞书妙记链接、"回复666/888""能听到吗"类互动语句、同一句话的重复表述（只留一遍最完整的）。
2. **去口语**：所有"对不对""你想想""比如说""我跟你们讲"类口语清除，转陈述句。
3. **观点化**：每节重写为紧凑的观点文——**是什么（定义）→ 为什么（原理）→ 怎么做（要点）**。一个观点一段，段内逻辑连贯。
4. **案例最小化**：案例不单独成段讲故事，压缩成**半句到一句**嵌进段落作佐证（背景+做法+结果）。多个例子说明同一道理时只留最有力的一两个。
   - **例外——话术/模板/清单是干货**：具体成交话术、文案模板、工具清单项、礼仪条目**整句整条保留**（加引号），不展开场景描写。
5. **保留**：
   - 章首 `> **本章要点**` 块（3-5 条提炼，自己写，忠实原文观点）
   - 小节标题（按课程内容脉络提炼，`## 8.1 xxx` 按章号编号）
   - 所有原理/方法名称、分类体系（如 DISC 四性格、马斯洛两板块）——**体系一项不能少**
   - 方法步骤（用"第一…第二…"嵌在段落里）
   - 核心金句、口诀（**原话保留，加粗**）
6. **禁止清单化**：整体是成段的文章，不是笔记大纲。列表每章最多 2 处（仅限真正需要步骤列表的地方）。
7. **错别字智能还原**：语音转写的同音字、行业词按上下文还原（"贝宁达→贝琳达""沾前顾后→踟蹰不前"）。
8. **体量控制**：每章给子代理明确的目标字数（≈ 原文字数 × 0.27），并强调"目标是密度不是删减——干货一个不能丢，丢掉的是水分"。

### 不同体裁的差异化处理

| 体裁 | 处理要点 |
|---|---|
| 主修课文字稿 | 质量较好，按标准流程走 |
| 直播逐字稿 | 水分最大：时间戳、互动、重复全删，缩水到 50% 左右属正常 |
| 会员答疑 | 保留"提问的行业背景一句话 + 拆解逻辑与方法"，答疑的价值在拆解思路 |
| 案例教学课 | 每个案例一小节：背景两三句 + 拆解要点 + 可复用结论 |
| 辅修短课 | 3000 字内的可以不分节，但"本章要点"块必须有 |
| 合并同题课 | 一版为主干通读整理，另一版通读后只挑"主干没有的"补入对应小节，重复一律不收 |

## 五、第四步：并行生产（多代理协作）

内容量大时（>10 万字）用多个子代理并行，单代理任务量控制在 **读入 ≤ 12 万字、产出 ≤ 1 万字**，超了就拆组。

### 给子代理的任务提示词模板（要点）

1. 角色设定：资深书籍编辑，产出直接可进 EPUB 的章节 Markdown；
2. 明确列出**源文件的绝对路径**（区分哪份是主干、哪份是补充）；
3. **完整粘贴提纯标准**（上面第四步的 8 条，一个字都别省）；
4. 明确**章号、章标题、小节编号格式、输出文件路径**（全书的编号体系要先定好，章号跨卷连续）；
5. 明确目标字数区间；
6. 要求回复"每章字数 + 小节标题清单"，便于验收；
7. 要求发现问题（源文件截断、内容缺失）**如实上报，不许自行虚构补全**。

### 执行节奏

- 按卷分波次并行（每波 2-5 个代理）；
- 每个代理完成后核对：字数达标没、小节结构合理没、有没有上报源文件问题；
- 单本大书也**分批验收**：第一卷先出 EPUB 试读版给需求方过目，口径确认后再铺开。

---

## 六、第五步：成书（EPUB 制作）

### 文件组织

```
制作目录/
├── chapters/          # 章节源稿（按卷分子目录，每章一个 .md）
│   ├── 卷一/第01章-xxx.md
│   └── …
├── build_epub.py      # 合书脚本
└── MANIFEST           # 脚本内的分卷结构定义（加卷只改这里）
```

### 技术要点

1. **纯 Python 标准库就能做 EPUB3**（zipfile 打包：mimetype 不压缩放最前 + container.xml + content.opf + nav.xhtml + toc.ncx + 章节 xhtml + css），不依赖 pandoc/ebooklib。
2. **MD→XHTML 转换**只需覆盖书里用到的语法：标题、段落、引用块、加粗、列表。注意 `html.escape` 转义。
3. **两级目录**（微信读书友好）：卷 = 一级（单独的卷封面页）、章 = 二级；nav.xhtml 用嵌套 `<ol>`，toc.ncx 同步。
4. **元数据**：`dcterms:modified` 必须有（EPUB3 要求），语言 `zh-CN`。
5. **正文 CSS**：`p { text-indent: 2em; text-align: justify }`、引用块加底色左边框，微信读书渲染正常。
6. 生成后**必须校验**：用 `xml.etree` 逐个解析包内所有 xhtml/opf/ncx，全部通过才算成品。
7. **MD 版顺带出**：同一份 chapters 源稿按 MANIFEST 顺序拼接成单文件 MD（卷标题用 `# 【卷名】` 区分层级），零成本多一个交付格式。

## 七、验收与迭代（和需求方的配合节奏）

1. **试读版先行**：第一卷出 `xxx（试读版·卷一）.epub`，让需求方在真实阅读场景（微信读书导入手机）里验。
2. **验收看四件事**：① 排版字体行距；② 小节标题粒度；③ 内容密度（保留率）；④ 文风（口语味去到什么程度）。
3. **口径一旦锁定，写进文档**，后续批次照单生产不再返工。
4. **如实交代缺陷**：源文件截断、某节课无实质内容、补写了哪些缺项——全部写清楚，不糊弄。

---

## 八、踩过的坑（前车之鉴）

1. **直播聊天流稿重复率极高**：同一段知识点被原样记录十几遍，不抽 Dry-run 直接全文丢给代理会浪费大量算力——先人工抽样看一份，把去重规则写进提示词。
2. **有的课聊天流里没干货**（内容在视频画面/音频里）：如实标注"该节无可提取内容"，不要硬凑。
3. **源文件截断**：转写稿可能在源盘就缺尾巴（甚至"如何送礼"整块缺失）。动笔前抽查文件结尾；缺的内容宁可标注缺失，也不能编。
4. **一遍成稿必返工**：第一版一定会被反馈"太多了"——所以第一卷用试读版快速收敛口径，比全书做完再返工省 5 倍工作量。
5. **目标字数要给区间不给单值**，且要解释"缩水的来源是水分不是干货"，否则代理会为凑数砍案例。
6. **EPUB 文件命名**：验收期叫"试读版"，定稿后再改名"整理版"，避免需求方拿错版本。

---

## 九、一页速查（下次直接照做）

```
① 盘点：数文件、抽样看质量、列重叠对照表、查截断
② 定口径：重叠处理 / 单本 or 分册 / 敏感内容 / 分卷结构（问需求方）
③ 提纯标准抄第四步的 8 条，写进每个子代理提示词
④ 并行生产：单代理 ≤12 万字入 / ≤1 万字出，按卷分波，章号全书连续
⑤ 成书：build_epub.py（纯 stdlib）→ XML 全量校验 → EPUB + MD 双格式
⑥ 验收：第一卷试读 → 口径锁定 → 其余批次照做
⑦ 交付时如实报告：字数对照表、保留率、源文件缺陷清单
```
