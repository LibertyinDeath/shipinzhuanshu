# 实战记录：过钱关 70 小时课程成书（2026-11-04）

> 本技能 v1.0 的全部参数与坑位源自这次实战。下次照此基线执行。

## 素材与算力

| 项 | 值 |
|---|---|
| 机器 | MacBook M5，10 核，16G 内存，macOS 27.2 |
| 视频 | 32 个 mp4，共 70.2 小时（先导 27h / 正课 32h / 加餐 11h），无内嵌字幕 |
| 转写引擎 | mlx-whisper + whisper-large-v3-turbo（Metal GPU，bf16） |
| 实测速度 | RTF 0.017-0.034（均值约 0.025），70 小时音频 1 小时 51 分跑完，31/31 零失败 |
| 转写字数 | 94.9 万字口语全文版（先导 40.7 万/正课 41.8 万/加餐 12.4 万） |
| 提纯产出 | 卷一 8 章 10 万字符（原稿 40.7 万→保留率约 25%），8 个代理两波并行 |

## 关键决策

1. **mlx-whisper 而非 faster-whisper**：faster-whisper 在 Mac 只吃 CPU（RTF 估 0.15-0.25 → 11-18 小时）；mlx 吃 Metal GPU，快 7 倍，准确率还更高（large-v3-turbo）。
2. **必须传本地模型路径**给 mlx_whisper.transcribe（`path_or_hf_repo=<snapshot目录>`），否则联网校验被代理 502。
3. **模型下载走 hf-mirror**（`HF_ENDPOINT=https://hf-mirror.com`），1.6GB 约 20 分钟。
4. **ffmpeg 静态二进制**：无 Homebrew 的 Mac，从 ghfast.top 镜像下 zackees/ffmpeg_bins v8.0 darwin_arm64.zip（40MB），ffmpeg+ffprobe 放 `~/.local/bin/`（已在 PATH）。

## 提纯执行记录

- 8 章 = 8 个代理，每波 4 个并行，每个代理 prompt 含：角色+源文件绝对路径+8 条提纯标准全文+章号/小节格式+输出路径+目标字数区间+如实上报要求
- 目标字数 = 原文字数 × 0.27 给区间（互动多的场允许更低）
- 每章产出：内容标题（无章号前缀）+ `> **本章要点**` 块 + `## N.M` 小节 + 列表≤2 处 + 文末「待核对」
- 波次完成即核字数/小节清单，两波约 40 分钟

## 打包修复记录（微信读书目录问题的完整排查链）

1. ❌ v1：只改 nav/ncx 标题 → 目录还是「第N章」（症状：目录没被读）
2. ❌ v2：全包去掉章号前缀+换 ID 换文件名 → 还是「第N章」（排除缓存论）
3. ✅ v3：发现 manifest 未声明 nav/ncx → 补 `properties="nav"` + ncx 声明 + `spine toc="ncx"` → 微信读书正确显示三级目录

教训：**阅读器显示「第N章」这种通用编号 = 它没读到目录，先查 manifest 声明，别先怀疑标题写法。**

顺带修复：加粗双重转义（`html.escape(inline())` 套娃导致微信读书显示 `<strong>` 字样）。
